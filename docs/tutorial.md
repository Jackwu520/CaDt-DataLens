## 1. 搜索排除表 search-ignore

### 解决什么

工作区里总有些目录不该出现在搜索结果里：构建产物、缓存、认知索引这类体积大、命中多的路径。排除表让这些路径从四处检索中一并消失：界面全局搜索、AI 的 `search_text` 与 `glob`、目录树 `list_dir`。一处配置，四处生效。

### 写在哪

工作区根目录下的 `.cadt/config/search-ignore`。没有这个文件就没有自定义规则，软件自带的忽略表照常工作，两套互不干扰。

### 语法

一行一条规则。解析时逐行去掉首尾空白，再按下面的规则处理。

| 写法 | 含义 |
|---|---|
| 空行、`#` 开头 | 注释，忽略 |
| `!` 前缀 | 取反，即「重新包含」 |
| 不含 `/` 的模式 | 按路径每一段的名字匹配，任意层级的同名文件或目录都命中 |
| 含 `/` 的模式 | 按相对工作区根的路径做 glob 匹配 |
| 开头的 `/` | 视为相对根，解析时去掉 |
| 结尾的 `/` | 目录标记，解析时去掉 |

glob 里 `*` 不跨目录，`**` 跨目录，`?` 匹配单个字符。

### 顺序决定结果

规则从上到下逐条判断，后匹配的覆盖先匹配的。`!` 不是「加白名单」的独立声明，而是把当前命中状态翻回「包含」——因此它必须写在你想要重新包含的那条排除规则之后。

```gitignore
# 排除所有 .aoci 目录（按名字，任意层级）
.aoci

# 但把其中一个子目录重新包含回来
!.aoci/keep
```

上面第二行要放在第一行之后才有效；调换顺序会被第一行覆盖掉。

### 两个容易踩的点

**按名字还是按路径，取决于有没有 `/`。** `dist` 会命中任意层级的 `dist` 目录；`/dist` 和 `dist/` 解析后仍是 `dist`，同样按名字匹配；只有写成含 `/` 的路径形式（如 `.cadt/tmp`、`docs/**/*.bak`）才按相对根的路径匹配。

**改动即刻生效，但按修改时间缓存。** 保存文件后下一次搜索就会重载，不需要重启。工作区根目录自身永不排除，从子目录发起的检索不受影响。

### 边界

这份表只作用于上面列出的四处检索。软件内置的硬编码忽略表（`SkipDir` / `SkipPath`）独立维护，工作区防护的结构指纹等也不读取用户配置——避免用户误配导致防护失效。

## 2. 生命周期钩子

### 解决什么

有些命令需要在特定时机自动跑：打开工作区时拉起开发服务器、提交用户输入前做一次检查、工具调用后记录日志。生命周期钩子把「时机」和「命令」绑成条目，到点自动执行，不必手动触发。配置入口在 设置 → 生命周期。

### 九个事件

事件分两组：工作区级只认工作区，AI 级跟会话或工具走。

| 事件 | 时机 | 执行方式 | 工具匹配 |
|---|---|---|---|
| `workspace-open` | 打开工作区（含切回、启动恢复） | 不阻塞 | 否 |
| `workspace-close` | 关闭工作区或切走旧目录 | 不阻塞 | 否 |
| `session-start` | 空会话第一轮开始前 | 阻塞 | 否 |
| `user-prompt-submit` | 每轮提交用户输入时 | 阻塞 | 否 |
| `pre-tool-use` | 工具调用前 | 阻塞 | 是 |
| `post-tool-use` | 工具成功后 | 不阻塞 | 是 |
| `post-tool-use-failure` | 工具失败后 | 不阻塞 | 是 |
| `permission-request` | 权限审批发起时 | 阻塞 | 是 |
| `stop` | 用户停止生成时 | 不阻塞 | 否 |

`ai-session-start` 是第一期留下的旧名，作为别名保留，读取旧配置时会自动改写成 `session-start`；新建条目时下拉里不显示它。

### 阻塞与不阻塞

「阻塞」指宿主流程会等命令跑完再继续，每条命令有自己的超时上限，失败不会阻断后续流程。不阻塞的事件后台执行，不等结果。

据此可以判断该把命令挂在哪：`session-start` 适合做「开始之前必须先完成」的初始化；`post-tool-use` 适合做「事后记录」，不该拖住主流程。

### 工具名匹配器

四个工具级事件（`pre-tool-use`、`post-tool-use`、`post-tool-use-failure`、`permission-request`）支持按工具名过滤，其余事件忽略匹配器。

| `matchTools` 写法 | 匹配范围 |
|---|---|
| 空数组 | 所有工具 |
| `*` 或 `all` | 所有工具 |
| `mcp__*` | 所有以 `mcp__` 开头的工具（前缀通配只支持 `__*` 这一种形态） |
| 具体工具名 | 仅该工具 |

匹配器最多 20 项，每项不超过 60 字符。

### 执行环境

- 工作目录固定为该工作区根，不提供逐条目的目录设置；需要在子目录执行，就在命令里自己 `cd`。
- 命令文本不超过 2000 字符；要指定 shell，在命令文本里写（如 `powershell -Command ...`），不作为条目字段。
- 自动合并「设置 → 环境变量」里配置的环境变量。
- 超时范围 1–600 秒，默认 30 秒。
- 上限：全局 20 条，单个工作区 10 条。

### 配置与 AI 代配

用户可以自己在设置页增删改条目，也可以让 AI 代配。AI 走 `app_control` 的四个动作：`get_lifecycle_hooks`、`add_lifecycle_hook`、`update_lifecycle_hook`、`remove_lifecycle_hook`。

三个写动作无条件弹审批卡，完全权限档也不例外——改命令文本等同于换一条命令，风险不随权限档变化。AI 只能操作当前窗口所在工作区的条目，且没有「立即执行」动作：要跑命令得走正常的命令执行审批链，不能借配置入口绕过。

### 为什么存在 localStorage

配置放在本机设置的 `localStorage`，不放应用数据目录，也不放工作区 `.cadt/`。这是安全选择：完全权限档的 AI 能直接写应用数据文件，配置放那里等于绕过审批拿到一个持久化后门；放工作区则等于「打开一个陌生仓库就自动执行命令」。AI 在设置里没有写入通道，审批因此不可绕过。

代价是配置与其余设置同命运，只在主动清理界面数据时才重置。

## 3. JSONPath 查询

### 解决什么

在 JSON 文件里找一个深层节点，肉眼翻很慢。JSONPath 用表达式描述路径，一次定位所有命中项，并可从结果跳回源码行。入口是 `Ctrl+Shift+J`；YAML、TOML、INI 复用同一份解析结果。

### 语法速查

`$` 表示根，可以省略。路径可以点号、方括号混用。

| 写法 | 含义 |
|---|---|
| `.key` | 取子键 |
| `['key']` / `["key"]` | 取子键，键名含特殊字符时用这种 |
| `[n]` | 数组下标，负数从末尾算 |
| `[start:end:step]` | 切片，`step` 默认 1，边界可省略 |
| `[a,b,c]` | 联合，取多个位置 |
| `*` | 通配，当前层所有元素 |
| `..name` | 递归下降，任意深度下名为 `name` 的节点 |
| `[?(@.age > 18)]` | 过滤 |

### 过滤表达式

过滤写在 `[?(...)]` 里，`@` 指当前节点。

比较运算符：`==`、`!=`、`>`、`>=`、`<`、`<=`。
正则匹配：`=~ /pattern/`。
逻辑运算：`&&`、`||`、`!`，可用括号分组。

```jsonpath
$.users[?(@.age >= 18 && @.active == true)].name
$..[?(@.status == 'error')]
$.items[?(@.title =~ /^草稿/)]
```

过滤里的字符串用单引号或双引号，数字直接写，`true` / `false` / `null` 是字面量。字段路径用 `@.field`，键名含特殊字符时用 `@['field']`。

### 边界

这是 JSONPath 的一个子集，覆盖常用的路径、切片、过滤与递归，不是完整标准实现。表达式为空、路径段缺失或语法非法时会报错，报错信息会指出问题位置。命中结果去重后展示，每条带完整路径，可跳回源码对应行。

## 4. 便签定位点

### 解决什么

便签面板里的内容没有文件路径，无法用普通路径引用。定位点是一种可复制的短字符串，用来精确指向某个分组或条目，便于交给 AI 或从命令行直接打开。

### 格式

```
cadt-memo://<作用域>/<block|item>/<id>
```

| 字段 | 取值 |
|---|---|
| 作用域 | `workspace`（工作区）或 `global`（全局） |
| 类型 | `block`（分组）或 `item`（条目） |
| id | 分组或条目的 id |

在便签面板里对分组或条目右键，选「复制定位点」即可得到。

### 两种用法

**交给 AI。** 把定位点粘贴给 AI 助手，它会按其中的作用域读取便签清单，再用 id 定位到对应分组或条目；折叠的分组会自动展开并高亮。

**命令行打开。** 作为 `--memo` 参数传给程序：

```bat
CaDt-DataLens.exe --memo "cadt-memo://workspace/item/it-xxx"
```

冷启动会直接打开便签面板并跳转；程序已在运行时，新命令转发到现有窗口处理。

## 5. 命令行定位

### 解决什么

从外部工具或命令行打开文件时，直接指定文件和行列，省去打开后再手动跳转。

### 写法

```bat
CaDt-DataLens.exe "D:\data\sample.json:42:8"
CaDt-DataLens.exe "D:\data\sample.json:42"
CaDt-DataLens.exe "D:\data\sample.json" --line 42
CaDt-DataLens.exe --line 42 "D:\data\sample.json"
CaDt-DataLens.exe -g "D:\data\sample.json:42"
```

- 行、列从 1 开始，列可省略。
- 参数形式：`--line` / `-l` 指定行，`--column` / `-c` 指定列，`--goto` / `-g` 用 `文件:行[:列]` 的紧凑写法。
- 可以一次传多个文件。
- 图片和二进制文件忽略行列。
- 程序已在运行时，新命令转发到现有窗口并定位，不会另起一个实例。
