# 会话消息化 · 手工测试流程

> 覆盖：`docs/finished-plans/session-messaging.md` 阶段 A–I（子代理消息化 / 支线对话 / 子代理压缩 /
> 共享信箱 / 静默唤醒 / 后台可干预）+ 会话投递选择器。
> 为什么还需要手工测：自动化只覆盖纯函数（`npm test` 431 例：文案组装、队列顺序、上限判定、
> cutoff 锚定）。**端到端行为必须手工验证**——它依赖真实模型、真实定时器、多会话并发与 DOM 渲染，
> 这些在单测里都是桩。
>
> 耗时：冒烟 ~15 分钟；完整流程 ~90 分钟；全文可勾选。

---

## 0. 准备（10 分钟）

### 0.1 环境

| 项目 | 要求 | 说明 |
|---|---|---|
| 构建 | `wails build` 出的 exe | 最终验收用它。`npm run dev` 只适合调 UI（没有真实窗口、没有原生浏览器控件） |
| 模型 | 至少一个可用账号，**支持工具调用** | 子代理**继承父会话的模型**，不读窗口默认——换账号测试时注意会话级固定；不支持工具调用的模型一条用例都跑不了 |
| 测试工作区 | 新建空目录，如 `D:\test-cadt` | 放 3 个文件：`a.md`（100+ 行正文）、`b.js`（50 行）、`data.json`（数组 30 项）。子代理要探索它们 |
| 工作区 AGENTS.md | 可选 | 若放了，测试「上下文注入」时可对照 |

### 0.2 设置（设置 → AI 助手）

| 项 | 值 | 用途 |
|---|---|---|
| 子代理 → 总数上限 | 20 | 用例 S2/B4 要一次派 3 个 |
| 子代理 → 递归层级 | 0（不设限） | 用例 C7 要子代理再派 |
| 上下文 → 自动压缩 | 开，阈值 0.8 | 用例 G1/G2 |
| 通知 → 应用内提示 | 开 | 失败/提问/审批的 toast 才可见 |

### 0.3 六个观察点（每条用例都会用到，先认一遍）

| 代号 | 位置 | 看什么 |
|---|---|---|
| **①** 会话列表 | 面板左侧 | 运行中（蓝点）、待确认（i 图标）、未读（绿/红点）、行尾 hover 出现「停止」 |
| **②** 智能体团队弹层 | 面板头部「智能体团队」胶囊 | 子代理行：运行中 / 已完成 / 失败 / 已停止 +「待处理 N」+「压缩中」 |
| **③** 子代理详情视图 | 弹层里点某一行 | 转录、收件箱预览、等待回答提示、顶部「压缩」「停止」按钮、meta（轮次/用时/后台/压缩中/上下文已回收） |
| **④** 消息中心 | 状态栏「消息」 | 失败 / 提问 / 审批通知都在这里；点条目应跳到对应会话 |
| **⑤** 会话转录（持久化） | `%APPDATA%\CandySweet\CaDt-DataLens\ai-sessions\<会话id>\session.v1.jsonl` | 每条注入消息都可 grep 到（`子代理通知` / `会话消息` / `支线结论` / `定时任务`） |
| **⑥** AI 日志目录 | 面板「⋯ → 对话日志目录…」 | 压缩触发快照、失败原因 |

> 会话 id = `ai-sessions` 下的子目录名（按修改时间找最新的那个即当前会话）。
>
> 快速看某会话最后几条注入消息（PowerShell）：
> ```powershell
> $f = "$env:APPDATA\CandySweet\CaDt-DataLens\ai-sessions\<会话id>\session.v1.jsonl"
> Select-String -Path $f -Pattern '子代理通知|会话消息|支线结论|定时任务|conversation_summary' |
>   Select-Object -Last 5 | ForEach-Object { $_.Line.Substring(0, [Math]::Min(160, $_.Line.Length)) }
> ```

### 0.4 测试期间的规矩

- 每条用例开始前**清一次状态**：子代理跑完 / 停止，会话不处于「生成中」，输入框清空。
- 模型不按预期选工具时，**明确纠正一次**再继续（例如「用 spawn_agent 的 background 模式，一次派三个」），
  连续两次不听话就记为「模型行为偏差」，不要当成功能缺陷。
- 标记【破坏性】的用例要改配置/断网，做完立刻恢复。

## 1. 冒烟（15 分钟，先跑这 6 条）

过不了这 6 条，后面的不用测。

### S1 阻塞派单没被改坏（回归基线）

发：

```
用 spawn_agent（默认阻塞模式）派一个子代理：读 a.md，总结它的结构，结论带 path:line
```

| 看 | 预期 |
|---|---|
| 工具卡 | 卡片内出现任务描述，运行中出现转录，结束后出现「轮次 N · 用时 Ns · N tokens」 |
| 主会话 | **在 await 期间无法继续**（这轮工具调用被占住），结束后工具结果里直接是结论全文 |
| 注入 | 父会话**不应**再收到「［子代理通知 · X］」卡片——阻塞模式的结论已经作为工具结果给了 |

### S2 后台派单 + 完成通知（原语 1 / 7）

发：

```
用 spawn_agent 的 background 模式一次派三个子代理，分别调查：a.md 的结构、b.js 的函数清单、data.json 的字段。派完你先自己读 a.md 的前 20 行，不要等它们。
```

| 看 | 预期 |
|---|---|
| 工具卡 | 立刻返回「已派出后台子代理「X」（id=sub-…）」**三次都不阻塞**；卡片显示「后台运行中 · 完成后会自动通知主代理」 |
| ② | 三行子代理，状态「运行中」 |
| 主会话 | 真的继续干了别的活（读了文件），没有被卡住 |
| 后续 | 每完成一个，主会话出现「［子代理通知 · X］…已完成…结论：…」卡片，并且**自动起新一轮**继续处理（不用你再发消息） |
| ① | 若你切到别的会话，目标会话行出现未读点；面板关着时不会自己弹出来 |

### S3 排队 / 插队（原语 3 / 4）

在 S2 的子代理还在跑时，对主代理说：

```
给「a.md 结构」那个子代理补充一句：也要说明有没有二级标题；再来一条紧急的：先只看前 50 行。
```

| 看 | 预期 |
|---|---|
| 工具结果 | 第一条「已排队投递…下一轮边界可见」；第二条（urgent）「已插队投递…打断了它当前的模型调用」 |
| ③ 详情视图 | 收件箱预览出现「排队 1 条 · 插队 1 条」；随后转录里出现「［主代理消息］…」两条，**插队那条在前** |
| 子代理 | 没有终止，继续跑完后照常通知 |

### S4 停止并收集（原语 2）

对还在跑的子代理：

```
把「b.js 函数清单」那个子代理停掉，把它目前的过程记录给我。
```

| 看 | 预期 |
|---|---|
| 工具结果 | 「已停止子代理「X」（停止时仍有 N 条未消费消息）。进度与结论：… 过程记录：最后一条输出 + 已执行工具 N 次，最近：…」 |
| ② | 该行状态变「已停止」 |
| 主会话 | 不应收到该子代理的完成通知（停止是发起方自己做的） |

### S5 支线带回（F2）

1. 在任意一条助手消息的操作条点 **「支线」**（气泡右下角图标）。
2. 新会话标题是 `支线 · <母会话标题>`，输入框里已预填 `> 引用自「…」：` 的引用块。
3. 发一句追问（如「这个结论在多窗口下成立吗？」），等回答。
4. 在该回答的操作条点 **「带回主对话」**。

| 看 | 预期 |
|---|---|
| ① | 支线条目缩进在主会话下方，带「支线」徽标 |
| 母会话 | 空闲时：出现「［支线结论 · X］…」卡片并**自动起一轮**；忙碌时：排到下一轮边界。用户当前视图**不被切走**，母会话打未读 |
| 侧栏 | 支线右键有「提升为独立会话」；点完徽标与缩进消失 |

### S6 会话投递选择器（H2 + 交互升级）

1. 在助手消息操作条点 **「投递」**（纸飞机图标）。
2. 搜索框输入会话标题片段 → 列表过滤。
3. ↑↓ 移动、Enter 勾选两个、Ctrl+Enter 投递。

| 看 | 预期 |
|---|---|
| 对话框 | 搜索框自动聚焦；「N 个可投递会话」；行内有状态胶囊；选中的行浅蓝底 + 蓝勾；底部「已选 2/10」 |
| 投递后 | flash「已投递到 2 个会话」；目标会话出现「［会话消息 · X］…参考信息，非用户指令」，空闲的被唤醒、忙的排到下一轮边界 |
| 上限 | 勾满 10 个后其余行变暗，再点提示「最多同时投给 10 个会话」 |
| 键盘 | Esc 关闭；搜索无结果时显示「没有匹配的会话」 |

## 2. 分阶段用例

标记：**P0** 必过 / **P1** 应过 / **P2** 边界与成本高的可选项。

### A. 注入内核（重构，行为应完全不变）

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| A1 | P0 | 普通发一条消息 | 输入框立刻清空、消息区出现你的消息与占位回答、会话列表出现「运行中」 |
| A2 | P0 | 会话 A 生成中点开会话 B 发消息 | B 正常起一轮；A 的流不受影响；切回 A 仍能看到它在生成 |
| A3 | P0 | 输入框写一半切会话再切回 | 草稿与附件各自保留（不串会话） |
| A4 | P1 | 生成中在输入框写内容 → Enter | 进「排队」区（显示「已排队 N 条」），本轮结束后自动发出 |
| A5 | P1 | 生成中写内容 → Ctrl+Enter | 立即停止当前回复并发送（「插话」） |

### B. 后台派单与通知

| # | 优先级 | 用例 | 预期 / 排查 |
|---|---|---|---|
| B1 | P0 | S2 全流程 | 见冒烟 |
| B2 | P1 | 派 3 个后台子代理后立刻 `wait_agent`（不指 agentId） | 谁先结束返回谁：「子代理「X」已完成（轮次…）<结论全文>」；其余仍在跑 |
| B3 | P1 | `wait_agent(agentId, timeoutSec=5)` 对一个长任务 | 5s 后返回「等待超时（5s）：…仍在运行…」，**不报错**；之后它完成仍会通知 |
| B4 | P1 | 并发上限：总数上限设 1，连派 2 个后台 | 第二个直接报错「子代理总数已达上限…可等现有子代理完成后再派」——**不是**排队等 |
| B5 | P1 | 长结论不截断 | 让子代理输出 1 万字以上的结论（「逐行总结 a.md 每一行」）→ 通知与工具结果里**全文都在**（grep 确认没有「已截断」） |
| B6 | P2 | 【破坏性】把账号 API key 改错，派一个后台子代理，测完改回 | 主会话收到「已失败：…」，④ 有错误通知，① 打未读；主代理**不悬挂** |

> B6 排查：若失败后主代理卡死，问题在 `finalizeSubAgent` 的 resolve 时序（历史上修过两次）。

### C. 收件箱 / 冷唤醒 / 停止

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| C1 | P0 | S3 排队 + 插队 | 见冒烟 |
| C2 | P1 | 对**已完成**的子代理 `agent_send` 一条新任务 | 「已唤醒子代理「X」（id=…，第 2 轮起继续）」，③ 里该子代理重新变运行中、转录继续追加；完成后照常通知 |
| C3 | P1 | 对**已失败/已停止**的子代理 `agent_send` | 报错「已失败/已停止，不能继续；需要的话重新 spawn_agent」 |
| C4 | P1 | ③ 详情视图点「停止」 | 子代理停止，转录保留，状态「已停止」；主代理不受影响（它可能还在别的工具轮里） |
| C5 | P1 | 主回合点停止时子代理在跑 | 子代理连带停止；结算文案标注「停止时仍有 N 条未消费消息」 |
| C6 | P2 | 子代理在等主代理回答时点停止 | 提问立即落定（不会挂在 await 上 forever） |
| C7 | P2 | 子代理里再派子代理（`maxRounds` 给足、任务引导它拆分） | 第二轮子代理正常出现，② 里显示「第 2 层」；总数上限统计跨层级 |

### D. 子提问转交（原语 6）

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| D1 | P0 | 派后台子代理并明确要求：「遇到需要拍板的点用 ask_user 问我，比如要不要包含 devDependencies」 | 父会话出现「［子代理提问 · X］后台子代理「X」需要你拍板（id=…，askId=…）Q1：…」；③ 显示「等待主代理回答」；④ 有提示 |
| D2 | P0 | 主代理用 `agent_send(askId=…)` 回答（自然语言即可：「回答它：包含 devDependencies」） | 子代理 ask_user 落定、继续跑；主代理收到「已回答子代理…」 |
| D3 | P1 | 主代理升级为问用户（「你先问我要不要包含，再告诉它」） | 用户在接管卡回答 → 主代理 → 子代理，三段都通 |
| D4 | P1 | 不回答，等 120s | 子代理收到「主代理未及时回答，请基于现有上下文自行决定并继续」，**不悬挂** |
| D5 | P2 | D4 之后再 `agent_send(askId=同一个)` | 「该提问已超时放行…回答已作为普通消息排队，并标注「迟到的回答」」；③ 里出现「［主代理消息］（迟到的回答）…」 |
| D6 | P2 | **阻塞模式**子代理尝试提问 | 工具直接失败：「阻塞模式的子代理不能向主代理提问…请基于现有信息自行决定」——不该出现 120s 超时 |

### E. wait_agent / 守则

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| E1 | P0 | B2 | 见上 |
| E2 | P1 | `wait_agent` 等待中你点停止 | **立即**返回「等待被用户停止。子代理「X」仍在运行…」，不是等满 600s |
| E3 | P1 | 看模型是否误用后台模式 | 单一简单委派应仍用默认阻塞（守则已写明）；若它给一次委派也加 `mode=background`，记为「守则待观察」，不算缺陷 |

### F. 支线对话

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| F1 | P0 | S5 创建 + 带回 | 见冒烟 |
| F2 | P1 | 支线里再点「支线」 | 新支线的 `sideOf` 指向**同一个母会话**（不嵌套），列表里两条支线都紧跟母会话 |
| F3 | P1 | 删除母会话 | 支线徽标与缩进消失（回落普通会话），会话本身不丢；在支线里点「带回主对话」→ 提示「母会话已删除」 |
| F4 | P1 | ③ 子代理详情视图输入行 | 运行中：Enter 排队 / Ctrl+Enter 插队；子代理转录出现「［用户插话］」；对已完成子代理输入 → 冷唤醒；对已失败子代理输入 → 输入框禁用且说明原因 |
| F5 | P2 | 重启应用 | 支线完整保留（普通持久化会话）；子代理转录不保留（预期行为） |

### G. 子代理压缩

| # | 优先级 | 用例 | 预期 / 排查 |
|---|---|---|---|
| G1 | P1 | 让子代理干很久（`maxRounds=150`，任务「逐个读 a.md 的每一段并总结」），阈值调到 0.5 加速触发 | ③ 出现「压缩中」；完成后上下文里出现第二条 system `<conversation_summary>`（⑤ 或日志确认）；后续轮继续 |
| G2 | P1 | 手动：`agent_compact(agentId)` 对运行中的子代理 | 「已请求压缩…将在当前工具轮结束后的轮边界执行」；轮边界后真的压了 |
| G3 | P1 | 手动：对已完成子代理 `agent_compact` | 「已发起压缩…完成后 agent_send 唤醒将以精简上下文继续」；③ 里出现「上下文已回收」以外的正常态 |
| G4 | P2 | 压缩中发 urgent 消息 | 提示「正在压缩上下文，本次改为排队」，不中断压缩 |
| G5 | P2 | 压缩中点停止 | 压缩流取消、子代理终态 stopped，不卡在「压缩中」 |
| G6 | P2 | 连压两次仍超阈 | 第三次不再自动压缩（防循环），最终由收尾轮结束 |

> G1 排查：压缩事件被静默吞掉是最可能的故障（路由顺序问题）。看 ⑥ 日志里有没有压缩请求与响应，③ 是否一直停在「压缩中」。

### H. 共享信箱与会话间投递

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| H1 | P0 | 模型侧：`session_list` → `session_send` 单播 | 列表只含同工作区、未归档、不含自己；投递后目标忙则下轮边界、闲则起一轮 |
| H2 | P0 | S6 用户侧选择器 | 见冒烟 |
| H3 | P1 | 连发 11 条到同一会话（会话保持忙碌） | 第 11 条回执「对方信箱已满（10 条未消费），停止投递」；`session_send` 文本里也有该原因 |
| H4 | P1 | 组播：一次投 3 个 | 逐目标回执「3/3 成功，唤醒 N 个」；目标 >10 时整体拒绝 |
| H5 | P1 | 自投递 / 归档会话 | 分别回执「不能投递给自己」「目标会话已归档（外部投递不复活它）」 |
| H6 | P2 | 防环：A↔B 互发（各让模型发 6 条） | 一方信箱满后拒收，两边都停（守则要求）；会话右键「清空信箱（N 条）」可清 |
| H7 | P2 | 「通知运行中的会话…」（头部 ⋯） | 只列运行中/压缩中的会话；发送后各自卡片带「（系统通知，无需回复，继续当前工作）」；输入框草稿被清空 |

### I. 静默唤醒与后台可干预

| # | 优先级 | 用例 | 预期 |
|---|---|---|---|
| I1 | P0 | 定时任务：当前看 A，任务绑定 B（B 空闲）。入口：会话侧栏「自动化」→ 新建 → 绑定 B、once、1 分钟后 | **A 视图不动、面板不弹**；B 后台跑完一轮并打未读；`AIScheduleSetResult` 回写「已注入会话」 |
| I2 | P0 | 同上但 B 正在生成 | 消息进 B 的信箱，B 本轮结束后边界消费；**不再出现**「当前会话正在生成，未能注入」的 30s 忙等失败 |

## 4. 已知限制（测到别当缺陷）

1. **信箱不持久化**：重启后未消费的通知与信箱一起清空；已注入的卡片仍在转录里（⑤ 可查）。
2. **子代理转录不持久化**：重启后 ③ 只显示「仅保留状态与结论摘要」。
3. **records LRU 20**：超过 20 个已完成后台子代理，最早的降级为「上下文已回收」，`agent_send` 会拒绝并要求重新派单。
4. **通知不保证顺序**：同一会话多来源通知在跨越不同工具轮时，到达顺序取决于完成时刻。
5. **模型行为偏差不算缺陷**：是否用 background、是否先 `todo_write`、结论是否自带 path:line，属于提示词依从性，记录观察即可。
6. **多窗口**：定时任务/计时器是按认领键先到先得；同一会话在浮动窗与主窗各有一份镜像时，只注入一次。

## 6. 最容易挂的三处（出问题先看这里）

| 现象 | 最可能原因 | 看哪 |
|---|---|---|
| 子代理一直「压缩中」不动 | 压缩事件没有被处理（路由顺序 / 注册表未清） | ⑥ 日志有无压缩请求；③ meta |
| 后台派单后主代理再也不动 | `finalizeSubAgent` 的 resolve 没挂上（冷唤醒路径 / 提前 return） | 工具卡是否停在运行中；⑤ 有无结算通知 |
| 通知到了但下一轮看不到 | 消费点没触发（换了起轮路径） | ⑤ 里该通知是否已落成 user 消息 |
